# Astral 项目宪法（CONSTITUTION）

> 状态：生效 · 建立：2026-11-01 · 适用范围：`astrbot_plugin_astral` 全部规格、实现与发布
> 效力：本文件约束所有规格包与实现决策。任何与本文冲突的设计，必须在对应 `decisions.md` 中显式记录并说明为何例外，否则视为缺陷。

## 1. 项目定位

Astral 是建立在 AstrBot 4.29.4（源码基线 `831abae85`）之上的插件。它在**不修改 AstrBot 源码**的前提下，把所有平台、所有群、所有私聊的 Agent 工作区指向同一个共享根目录，并在其上提供文件式的自我认知与长期记忆（`SOUL.md` / `MEMORY.md`）。

两条产品承诺：

1. **一个工作区**：任何会话里的 Agent，cwd 与文件读写基准都是同一个目录。
2. **一份记忆**：Agent 的自我认知与长期记忆是两个可读、可改、可迁移的 Markdown 文件。

## 2. 不可协商的原则

### P1 不改 AstrBot 源码

只允许运行期 monkeypatch 与插件公开扩展点；禁止修改 `../AstrBot-code`、禁止改 `dashboard/dist`、禁止通过打包/容器手段覆盖核心文件。

- 判定：代码评审时，改动只出现在插件目录内；`../AstrBot-code` 的 `git status` 干净。
- 违规示例：直接编辑 `astrbot/core/workspace.py` 或替换 `dashboard/dist` 里的静态资源。

### P2 补丁必须可逆、可观测、失败要吵

- **可逆**：`terminate()` 必须把每个被改写的模块全局还原；还原后行为与原生一致。
- **可观测**：`GET /astrbot_plugin_astral/state` 必须能回答"装了没、根是哪个、哪些消费者走的是补丁"。
- **失败要吵**：函数改名、函数缺失、黑名单命中、根不可写 —— 一律显式报错（日志 ERROR + 状态接口 503/`installed:false` + 聊天指令可见），**禁止静默回落默认值**。

- 判定：断掉补丁（模拟函数改名）后，`/astral status` 必须显示未安装且给出原因，而不是显示"一切正常"。

### P3 版本基线锁定，升级必须回归

所有源码坐标以 `specs/001-shared-workspace/plan.md` §8 的核对表为准，基线 commit `831abae85`（AstrBot 4.29.4）。规格文档**不得**自行发明行号；升级 AstrBot 后必须重跑回归清单（`specs/001-shared-workspace/plan.md` §9）并更新核对表。

- 判定：spec/plan 中出现的行号能在核对表中找到；跨大版本升级未回归即视为未验证。

### P4 记忆是文件，不是数据库

明确禁止：SQLite/其它数据库存记忆、embedding 与向量检索、LLM 自动抽取记忆、记忆专用工具集、群/用户分域的记忆作用域。
记忆的唯一载体是共享根下的 `SOUL.md` 与 `MEMORY.md`，由 Agent 使用 AstrBot 自带文件工具读写。

- 判定：`requirements`/导入清单里不出现 `sqlite3`、`embedding`、向量库；`002` 之外的文档不得描述记忆表结构。

### P5 完全共享 = 隐私必须透明

工作区与记忆对所有人（含所有群）可见。因此：

1. README 与插件页必须写明"以 Agent 身份从事管理操作的另一个人/admin 能看到共享目录里的东西"；
2. 首次启动/首次启用记忆时，日志与聊天指令必须给出一次可见提示；
3. 文档必须提示：**不要把密钥、口令、第三方隐私写入工作区或记忆文件**；
4. AstrBot 官方备份不包含工作区文件，README 必须提醒单独备份共享根。

- 判定：新用户仅阅读 README 就能知道"跨群可见"与"需单独备份"两件事。

### P6 安全护栏不可静默降级

`shared_root` 命中危险路径黑名单时，安装失败并报错；不得自动换成默认目录、不得只打一条 WARNING 就继续。同理：`files` 只读接口必须限制在共享根内、拒绝符号链接逃逸、限制单文件大小。

- 判定：把 `shared_root` 配成 AstrBot 源码目录 → 启动后 `/astral status` 显示安装失败且原因可读。

### P7 KISS：先解决真问题

- 不引入新依赖（`filelock` 已在 AstrBot 依赖中，可直接用；其它第三方库需在 `decisions.md` 说明必要性）。
- 不为了"以后可能"预先抽象；不新增配置项除非有明确使用场景。
- 单文件职责清晰：`ws_shared.py`（补丁）、`snapshot.py`（记忆快照）、`templates.py`（默认文案）、`main.py`（装配）。

- 判定：新增模块/配置项时，能在 `decisions.md` 找到"解决哪个具体问题"。

### P8 术语与编号必须先定义再使用

- 术语见 §5；规格编号规则见 §4。
- 同一概念在不同文档中必须同名；跨包引用必须指明 `001/002 + 编号`。
- 路径写法见 `specs/README.md` §0：本仓库根 = 插件目录（= 将来 DSH 工作区根），AstrBot 源码一律写 `../AstrBot-code/<path>`，调研材料写 `../_investigation/<path>`。

- 判定：全文检索同一概念只有一个称呼（例如不得混用"工作区根/共享目录/工作区"指同一物）。

### P9 代码风格与语言

- 代码注释与日志：英文（与 AstrBot 仓库约定一致）。
- 用户可见文案（指令回复、页面、README、规格文档）：中文。
- Python 3.10+；路径一律 `pathlib.Path`；跨平台（Windows/macOS/Linux、x64/arm64）。

### P10 规格先于实现，验收先于提交

- 每条功能需求必须有至少一条可验证的验收标准；没有 AC 的 FR 视为未完成需求。
- 实现提交时必须附对应 `T-n` 与已通过的 `AC-f.n` 清单。
- 本会话只产出 `specs/`，不写业务代码；实现另开会话。

## 3. 质量门禁（发布前必须全绿）

| 门禁 | 内容 | 判定方式 |
| --- | --- | --- |
| G-1 坐标 | `specs/001-shared-workspace/plan.md` §8 的 4 个函数在基线版本中签名一致 | 手工核对 + `status()` 的 consumers 非空 |
| G-2 双写 | 只改模块属性时消费者仍返回旧路径（负对照） | pytest / harness 断言 |
| G-3 还原 | `uninstall()` 后所有模块全局回到原函数、行为回到按 UMO 分目录 | pytest / harness 断言 |
| G-4 幂等 | 连续 install 3 次、reload 多次不叠加 | pytest + 手工重启 3 次 |
| G-5 护栏 | 黑名单、只读接口越界、超大文件三类拒绝路径均有用例 | pytest |
| G-6 快照 | 快照在对话内字节稳定、跨对话重建、截断与降级均有断言 | pytest |
| G-7 文档 | FR/AC/T/ADR 编号连续、无悬空引用、术语一致 | 自查清单 |
| G-8 回归 | harness 至少在非沙箱环境完整跑过一次（73 条） | 记录输出 |

未通过 G-1..G-8 的版本不得打 tag、不得写 CHANGELOG 的"已发布"。

## 4. 规格编写规范

1. 每个规格包固定四个文件：`spec.md`（要什么）、`plan.md`（怎么做）、`tasks.md`（怎么拆）、`decisions.md`（为什么）。
2. `spec.md` 只描述行为与验收，不写实现细节；实现细节放 `plan.md`。
3. 编号连续且被引用：
   - `FR-n` 功能需求（包内自增）；`AC-f.n` 验收标准（`f`=所属 FR 号、`n`=该 FR 内序号，如 `AC-3.4`）；`NFR-n` 非功能要求；`T-n` 任务；`ADR-n` 决策；`U-n` 未决问题。
   - 跨包引用格式：`001 FR-7`、`002 AC-3.2`。
4. 每条 AC 必须可执行：给出命令、观察点、断言三者之一，禁止"完善""合理""尽量"这类表述。
5. 假设必须显式：不确定的事实写成「假设：…」，并同步登记到该包 `decisions.md` 的未决问题表。
6. 大型更新（跨模块 / 破坏性 / 重构）才写 `delta.md`，并包含可执行的迁移与回滚步骤；本次为立项，不写 `delta.md`。

## 5. 术语表

| 术语 | 定义 | 不叫 |
| --- | --- | --- |
| 工作区（workspace） | AstrBot 中 Agent 本地执行时的 cwd 与文件读写根 | 项目目录、会话目录 |
| 共享根（shared root） | Astral 指定的唯一工作区根目录，所有会话共用；默认 `<data>/workspaces/astral` | 共享目录、根路径 |
| 双写 | 同时改源模块属性与所有已导入调用方的同名全局 | 双向 patch |
| 消费者（consumer） | 通过 `from astrbot.core.workspace import ...` 持有解析函数引用的模块 | 调用方 |
| 记忆文件 | 共享根下的 `SOUL.md` 与 `MEMORY.md` 两个 Markdown 文件 | 记忆库、记忆数据库 |
| 冻结快照（快照） | 对话开始时根据记忆文件渲染、在本对话内不再变化的上下文片段 | 缓存、注入块 |
| 首启播种 | 插件首次启动时在共享根创建缺失的模板文件，已存在则不动 | 初始化 |
| 托管区段 | `EXTRA_PROMPT.md` 中由 Astral 重写的 `<!-- astral:managed:begin/end -->` 区间 | 自动区段 |
| 只读页 | `views/astral/` 下的插件页面，仅展示状态与文件内容，不提供编辑 | 管理台 |
| 对话（conversation） | AstrBot `conversation_manager` 管理的对话记录，`/new`、`/reset` 会切换 | 会话（会话=session，由 umo 标识） |
